# node-insecure-random

**Flags:** `Math.random()` used in an assignment to a variable whose name
looks security-sensitive (contains `token`, `session`, `secret`,
`password`, or `otp`, case-insensitive).

**Why it matters:** `Math.random()` is not cryptographically secure — it's
seeded and generated by a fast, predictable PRNG intended for things like
UI jitter or sampling, not security tokens. Given enough output, or in some
implementations even a single output, an attacker can predict or recover
the generator's internal state and future/past values, making
`Math.random()`-derived tokens or session IDs guessable.

**Fix:** use `crypto.randomBytes()` (or `crypto.randomUUID()` for a
UUID-shaped value) for anything security-sensitive — tokens, session IDs,
OTPs, password reset codes.

```javascript
// Flags this:
const sessionToken = Math.random().toString(36);

// Prefer this:
const sessionToken = crypto.randomBytes(32).toString("hex");
```
